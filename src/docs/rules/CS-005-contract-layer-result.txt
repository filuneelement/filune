각 계약의 책임
HiddenStemSystemContract: 체계 ID/버전·역할/표시 순서·table 참조·호환성 검증 기록.
  실제 row 데이터 공급 없음. HiddenStemEntry schema는 complete/partial/unknown을 구별한다.
RelationFactContract: 존재/부재/미확인, 종류, entity·방향·scope·coverage·producer 참조.
  작용 강도/역할/길흉을 담지 않는다. coverage는 선언을 검사하며 계산하지 않는다.
RuntimeStateContract: active/weakened/stopped/unknown 기능 상태,
  local/inherited provenance, established/unchanged/restored/unresolved 전이를 분리한다.
LuckCarryStateContract: 최초 원국 변화, 원인 application, 기간, 소비 scope,
  여섯 snapshot 구획, 과거 처리 ledger. 저장/호출 순서의 owner는 지정하지 않는다.
EvidenceContextContract: 여섯 sourceType, claim별 검증·revision·optional hash·usage.
  문서 존재/파일 hash/승인 출처를 자동 confirmed 또는 runtime 승인으로 바꾸지 않는다.
RoleStateContract: 구조/entity 대상, 문서 assertion 또는 application-backed 결과의 구조.
  역할을 선정하지 않는다. 문서 assertion은 reference-only이며 runtime 정답 주입 금지.

validation
- unknown 입력에서 parse/is로 검사. ContractValidationError에 경로·이유 포함.
- plain JSON object/필수 필드/enum/자료형/빈 ID/알 수 없는 추가 필드/중복 ID 검사.
  accessor 필드는 실행하지 않고 거부한다. parse는 원본을 수정하지 않고 복제한다.
- 지장간 main/middle/residual 의미와 source display 순서를 분리한다.
  기본 체계명·역할 순서·검증 완료 시 증거·entry completeness를 검사한다.
- 관계 종류별 참가자 수, 생극 방향, entity part, stage 직접 비교 범위를 검사한다.
  부재는 complete coverage의 조사된 참가자 집합에서만 허용한다.
- 기능/출처/전이 조합, 정성 약화 표현/Rule 참조, 복원 근거/재평가 application을 검사한다.
  단순 같은 글자 재등장을 복원 근거로 허용하지 않는다.
- 원국 대상 변화만 carry 가능. 최초 원인/상태/기간 유지, 하위 stage 진행,
  유효기간, 중복 change 소비, snapshot/처리 ledger 참조를 검사한다.
  운끼리 약화 이력은 carry 원국 변화로 취급하지 않는다.
- inherited는 원본 기능/기간/원인을 보존한다. restored는 만료 기록과 재평가를 요구한다.
- 같은 Rule의 scope별 application instance를 참조할 수 있다.
  기존 evaluator의 application ID 구현은 변경하지 않았다.
- 증거·state predecessor cycle, 누락된 참조, 기대값의 직접/간접 runtime 유입을 거부한다.
- 정확 UTC 기간의 순서/겹침/만료를 검사한다. 불확실 carry/복원 경계에는 uncertainty가 필요하다.
  절입·간지·대운·관계·역할·길흉을 새로 계산하지 않는다.
- OperatorReview/Publication 상태나 문서 literalStatus를 대응시키는 코드는 없다.

검증의 한계
Schema는 producer의 주장/검증 기록 구조를 확인한다. 실제 명리적 진실, 독립 도구의
계산 계통 독립성, 모든 관계 조사의 완전성, 실제 역할 판단의 올바름을 입증하지 않는다.
confirmed는 선언한 claim과 근거 범위의 검증 기록이지 외부 검증을 실행한 결과가 아니다.
개별 schema는 shape·local invariant를 검사하고 bundle schema가 외부 참조를 해석한다.
partial/unknown 계약 데이터가 schema를 통과할 수 있지만 evaluator 준비/발행 허가는 아니다.

남은 runtime 연결 blocker
1. 문서 기본 지장간 row와 기존 표의 차이를 검증한 공급자가 없다.
2. 관계 후보·coverage를 공급할 기존 함수/자료의 책임과 버전이 미확정이다.
3. 출생 시각 범위·역산·역사 시차·독립 계산 증거 공급 연결이 없다.
4. 기대값 주입 없이 RoleState를 생성하는 실제 역할 판단 경계가 미확정이다.
5. scope별 실행/상태/기간/승계 ledger를 기존 실행기에 연결할 orchestration 책임이 미확정이다.
이 blocker는 contract layer의 완료를 막지 않았고 실제 runtime 준비와 구별한다.

다음 단계에서 먼저 결정할 사항
우선 지장간·관계·evidence 공급 경계/버전/owner를 정하고,
그다음 scope snapshot/application instance를 호출자가 공급할지 실행기가 구성할지 결정한다.
역할 결과를 자동 생성하지 않는 초기 구조 단계와 역할 포함 회귀 단계의 범위를 구분한다.
OperatorReview/발행 정책 및 문서 상태 대응은 별도 후속 결정이며 자동 승인하지 않는다.
