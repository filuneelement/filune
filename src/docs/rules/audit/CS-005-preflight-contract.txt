FILUNE CS-005 preflight contract — 설계 보고
범위: 입력·상태·증거 계약 제안. 구현 승인이나 새 명리 규칙이 아니다.
기준: A rev179, B rev38, C rev215, D rev152, 25-7 rev16 및 기존 mapping 7개.
기존 코드 읽기: canonical/types.ts, canonical/calculateCanonicalChart.ts,
judgment/types.ts, judgment/facts/fromCanonical.ts, dayRelationships.ts,
hiddenStemRoleTable.ts, calculateGreatLuck.ts, calculateYearlyLuck.ts,
calculateMonthlyLuck.ts, solarTermPillars.ts.
이번 산출물은 이 TXT 보고서뿐이다. 코드·mapping·fixture·테스트 변경 없음.

1. Canonical에서 바로 쓸 수 있는 입력

용어 구별:
- CanonicalChart는 CalculatedChart.chart의 원국 4주·basicRelations 부분이다.
- 절입·대운·세운·월운·시간정책은 바깥 CalculatedChart에 있다.
- “바로 사용”은 값의 읽기/재사용 가능을 뜻한다. 문서 준수·독립 검증 완료를 뜻하지 않는다.
- 기존 confirmed는 legacy-filune-jst-v1 아래의 확정이며 FILUNE 문서 인증과 다르다.
- C/P/U/X = confirmed / provisional / unknown / unsupported.
- 필수 입력이 U/X면 값을 만들어 채우지 않는다. provisional은 불확실성을 유지한다.
- AssessedValue는 C/P에 value가 있고 U/X에는 없다. 현재 CalculationAvailability의
  available을 독립 검증 완료나 문서상 confirmed로 승격하지 않는다.
- 아래 field 이름 중 기존 JSON pointer 외의 이름은 제안 계약이며 아직 타입이 아니다.

4. CS-005 상태 모델 제안

다음은 schema 설계 표기이며 실제 값이 들어 있는 fixture나 TypeScript 코드가 아니다.

FactEnvelope<T>:
 {id, kind:calculated/derived, value(사용가능할 때만), assessment:C/P/U/X,
  originRef, inputFactIds, producerVersion, uncertaintyIds}
originRef는 구별 union:
 - canonical: canonical schema version + canonicalPointer
 - derived: producer reference + inputFactIds
 - document: document/revision/section/location/hash
문서 해석 자체를 calculated/derived fact로 둔갑시키지 않는다.

JudgmentContext:
 {contextId, canonicalRef, documentManifestRef, asOf, targetPeriodRef,
  requestedStage:natal/great/year/month, birthEvidenceRef, uncertaintyRefs}
연산 기준시각과 절기 운 기간은 별도다. 임의 출생시각을 asOf로 대신하지 않는다.

EntityRef:
 {entityId, origin:natal/great/year/month, periodId?, position?, part:stem/branch,
  calculatedFactId}
같은 글자도 entityId가 다르다. position은 원국에만 허용한다.

DerivedFacts:
 {factEnvelopes, hiddenStemCandidates, tenGodFacts, positionFacts,
  periodCandidates, relationCandidates, coverage}
합거·유리함·상신 유지 등 판단은 이 객체의 선계산 값이 아니다.

ExposureDecision:
 {stemEntityId, monthHiddenStemFactRefs, classification?, functionDecisionRef?,
  applicationRef, evidenceIds, state:evaluated/deferred/not-evaluated}
투출 분류 이력과 현재 기능 상태를 서로 덮어쓰지 않는다(I-02a).

RelationshipDecision:
 {candidateRef, scopeId, participants:EntityRef[], applicability,
  effectCategory?, targetEntityIds, applicationRef, evidenceIds, uncertaintyIds}
- applicability: evaluated/not-applicable/deferred/not-evaluated
- effectCategory 예: 합거 / 합이불합 / 작용력 약화 / 성질 유지 / 오행 강화.
  실제 채택은 해당 원문 규칙의 표현과 적용 결과로만 한다.
- 강도는 원문 범주(예: 상당히 약화, 크게 약화, 일반/강한/매우 강한)를
  rule reference와 함께 기록한다. 숫자 비율 또는 순서 점수로 정렬하지 않는다.
- 관계 존재와 영향은 분리한다. 관계 없음은 completeness 확인 뒤에만 표현한다.

RoleState:
 {scopeId, assignments:[{entityRef, role:용신/상신/병/구응,
   applicationRef, evidenceIds, uncertaintyIds}], completionState}
상신 丙이라는 회귀 기대값을 이 필드의 초기값으로 넣지 않는다.
원고의 역할 판단은 EvidenceContext의 문서 근거이고 runtime assignment는 평가 결과다.
역할 선정을 평가하지 않은 최소 단계에서는 completionState가 미완료다.

FunctionalDecision:
 {entityRef, scopeId, category:유지/정지/약화/미평가,
  relationshipDecisionRefs, applicationRef, evidenceIds}
“영향을 받지 않음”과 “합거되지 않아 기능 유지”를 동일시하지 않는다.

NatalChange:
 {changeId, natalEntityRef, category, creatingApplicationRef,
  sourceStageSnapshotRef, effectivePeriodRef, evidenceIds, uncertaintyIds}

LuckCarryState:
 {entries:[{natalChangeRef, sourceSnapshotRef, effectivePeriodRef}],
  exclusions:[{sourceDecisionRef, reason, ruleRef}]}
운끼리 약화는 원국 변화가 아니므로 carry entry가 아니다(OP-L02).
상위 운 글자 자체를 하위 직접 비교 entity로 복사하지 않는다(OP-L01).

StageSnapshot (A OP-L02 여섯 정보의 대응):
 {snapshotId, contextRef,
  natalStructureRef,                    ① 원국 구조
  natalInternalDecisionRefs,            ② 원국 내부 합거
  inheritedNatalChangeRefs,             ③ 유효 상위 운의 원국 변화
  currentLuckPairDecisionRefs,          ④ 현재 운끼리 합
  currentLuckNatalDecisionRefs,         ⑤ 현재 운–원국 관계
  outgoingCarryStateRef,                ⑥ 다음 단계 승계 상태
  roleStateRef?, functionalDecisionRefs, axisDecisionRefs?,
  evidenceIds, uncertaintyIds, executionStatus}
상태 추가 시 기존 snapshot을 수정하지 않고 새 평가 결과로 추적 가능하게 한다.

AxisDecision:

- 丙午 세운 snapshot: 2027.1을 포함하는 입춘 전 월운의 부모 상태.
- 丁未 세운 snapshot: 2027 입춘 이후의 별도 부모 상태. 2027.1의 부모가 아님.

“2027 세운 상태”와 “2027년 1월”은 연도 숫자만으로 연결할 수 없다.

6. 기존 judgment 타입 수정 필요 여부

필요: YES (향후 구현 때; 지금 수정하지 않음).
- JudgmentFact는 canonicalPointer:string을 강제한다. derived/document origin을
  정확히 표현하려면 originRef union 또는 별도 Fact 타입이 필요하다.
- 기존 fromCanonical은 birthInput·solarTerms·timePolicy를 투영하지 않는다.
  위 데이터가 CalculatedChart에 있어도 현재 evaluator facts에 자동 공급되지 않는다.
  fromCanonical을 계산기로 바꾸지 말고 별도 허용 projection/증거 입력 경계를 정해야 한다.
- JsonValue만으로 역할·관계·유효기간·carry 불변조건을 보장할 수 없다.
  typed runtime state와 application/evidence ref 계약이 필요하다.
- RuleReference는 rule source 추적에 재사용 가능하지만 독립 계산 관측과 출생
  provenance 전부를 나타내지는 못한다. EvidenceContext를 별도 둔다.
- 현 uncertainty code는 출생시각 미상·절입·진태양시·성별 4개에 한정된다.
  문서 체계 불일치·출처 부족·승계 미확정은 별도 runtime uncertainty로 표현한다.
- CanonicalChart 확장은 우선 제안하지 않는다. 판단별 실행 상태는 별도 snapshot에 둔다.

7. OperatorReview / Publication 분리 제안

분리 필요: YES.
RuleExecutionStatus:

C-05/08/09는 기존 계산 재사용, 나머지는 위 계약을 갖춘다는 조건이다.
이 묶음의 최소 출력은 entity별 합거/약화/재사용 제외/기능 상태와 근거·승계다.
“기능 유지 entity가 상신이다”까지 확장하려면 I-01·I-02·I-02a·I-03·I-04·I-04-1,
I-04a·I-04c·I-05·I-07·I-14 및 관련 지지 규칙·OP-P01·03 계약이 더 필요하다.
상신 역할을 미리 넣지 않으므로 구조 묶음만으로 “상신 丙 유지 검증 완료”라고 하지 않는다.

IR-01은 후보 57개에 추가 집계하지 않았지만 OP-L02의 적용 해석 참조로 유지한다.
OP-T11/OP-R01~03 제외, I-04b 비적용 확인 범위는 그대로다.

10. 구현 시작 가능 여부: NO

기존 값 재사용 가능성과 evaluator 구현 준비 완료는 다르다.
관계 후보 공급 공백, 지장간 체계 불일치 확인, 출생 범위/독립 증거,
역할·기능·승계 계약이 미확정이므로 CS-005 evaluator 구현 착수 준비는 완료되지 않았다.
이 보고서는 schema 설계 제안만 제공한다. 실제 명리 규칙·새 계산식·AI·UI·테스트·
fixture·OperatorReview 매핑을 만들지 않았으며 여기서 멈춘다.
