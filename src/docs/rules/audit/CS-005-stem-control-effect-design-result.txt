CS-005 천간 극 기능 Effect 설계 검토 결과
검토 기준 A rev180 · D rev153 · C rev215와 현행 judgment contract

1. 일반 규칙 채택 가능 여부 — YES
유효한 천간 극의 도달을 입증한 기능마다 동일한 weaken을 기록할 수 있다.
관계 존재, 현재 작용 자격, 기능 귀속과 작동, 최종 해석 중요도를 각각 검증한다.
설계 채택과 2027.02 운영 결과의 독립 확정은 별개다.

2. A 실제 삽입 문안
삽입 위치 제안 — A-8-8 OP-P01 다음. 새 Rule ID는 문서 승인 시 부여한다.

“OP-L01·OP-L02에 따라 직접 비교 범위와 승계 상태를 확인하고,
현재 작용 가능한 천간의 유효한 극이 현재 작용 가능한 대상 천간의
특정 기능에 실제로 도달하면, 해당 기능을 weaken으로 기록한다.
극만으로 기능 정지를 판정하지 않는다. stop은 합거 등 별도의
정지 규칙에서 정지 범위와 유효기간이 확인된 경우에만 적용한다.
대상 천간에 여러 기능이 귀속되면 현재 scope에서 작동하고 극이
도달한 기능마다 독립적으로 weaken을 기록한다.
source나 target이 stopped인 동안에는 현재 극 효과를 산출하지
않으며 구조 관계와 역할 이력을 보존한다. weakened는 자동 제외
사유가 아니며, 현재 유효한 작용을 평가한다. 추가 약화는 별도
규칙이 없는 한 수치화하지 않는다.
기능 약화와 최종 해석상 중요도는 별도로 판단한다. 용신·상신 등
핵심 구조 기능의 약화는 핵심 구조 역할이 없는 일반 십성 기능의
약화보다 해석상 중요하게 다룬다. 병·구응과의 연결을 확인하여
최종 의미를 판단한다.”

3. D 테스트 문안
삽입 위치 제안 — D H-3-3 규칙 단위 합성 테스트. H-5-2에 대응을 연결한다.

- 일반 십성 기능. 관계·상태·도달·기능 근거가 충족되면 해당 십성에
  weaken 1건. 구조 역할 참조 없이도 일반 기능을 기록할 수 있다.
- 용신 기능. 대상 entity에 귀속된 현재 용신 역할과 도달이 확인되면
  용신 기능에 weaken 1건. 원고 표기만 주어진 대조 입력은 확정 0건.
- 상신 기능. 대상 entity에 귀속된 현재 상신 역할과 도달이 확인되면
  상신 기능에 weaken 1건. 타 entity 또는 만료된 역할은 확정 0건.
- 복수 기능. 하나의 관계에서 같은 대상의 십성·용신·상신이 각각
  입증되면 같은 relationFactId와 서로 다른 targetFunctionId로
  weaken 3건. 입력 재처리 시 같은 ID를 재현하고 중복 발행하지 않는다.
- stopped. source만 stopped, target만 stopped인 입력을 각각 검증한다.
  관계 fact는 보존하고 현재 극 효과는 각각 0건이다.
- weakened 및 미확정. source 또는 target이 weakened여도 작용과 도달이
  입증되면 weaken을 기록한다. 범위 밖, 도달 미입증, 상태 unknown은
  confirmed 0건이다. 약화 횟수나 강도를 자동 합산하지 않는다.
- 해석 분리. 세 기능의 effectType이 모두 weaken이고 Effect Fact에
  길흉·중요도·강도 필드가 없음을 확인한다. 같은 불리한 맥락에서
  용신·상신은 일반 십성보다 중요하게 해석한다. 용신과 상신의 상호
  순위는 고정하지 않는다. 병·구응 연결은 해석에서 검증한다.
- expected 값 미사용. producer에는 독립 계산한 관계·상태·기능·역할
  근거만 전달한다. expected는 산출 이후 비교 전용이다. expected를
  제거하거나 바꿔도 producer 출력이 동일한지 확인한다.
- 2027.02 통합 회귀. 1월 정지 상태의 만료, 입춘 이후의 세운/월운
  범위, 동명 壬의 entity 분리, 운합 및 승계 처리 후의 현재 상태를
  먼저 재현한 뒤 효과를 비교한다. 요청에 제시된 active 케이스는
  합성 테스트에서 검증한다.

4. 2027.02에서 confirmed 가능한 Effect Fact
요청의 전제와 기능별 도달이 독립적으로 입증되는 경우의 결과다.

  source              target             targetFunction   effect
  월운 壬             원국 월간 丙       편인             weaken
  월운 壬             원국 월간 丙       용신             weaken
  월운 壬             원국 월간 丙       상신             weaken
  원국 일간 戊        월운 壬            편재             weaken

앞의 3건은 같은 방향의 Relation Fact를 공유한다. 戊 → 壬은 별도
Relation Fact를 사용한다. 원국 시간 壬은 월운 壬과 별개다.
용신·상신의 약화는 후속 해석에서 중요하게 다룬다. 월운 壬 편재는
핵심 역할이나 별도 손상 경로가 확인되지 않으면 상대적으로 낮은
중요도로 검토한다. 병 작용의 완화 여부에 따라 해석 방향이 달라질
수 있으므로 戊 → 壬에 부정 의미를 자동 부여하지 않는다.

현행 저장소에서 이번 검토로 독립 확정한 건수는 0건이다.
C rev215 C-1 ⑥은 세운 丁–원국 시간 壬 합거 후 월운 壬 독립 작용과
壬 → 丙을 제시한다. A rev180 OP-T10은 현재 범위의 운끼리 합을 먼저
검사하고, OP-L02는 이미 확정된 원국 변화를 승계한다. 실제 월운 壬의
active/weakened 여부는 부모 세운 snapshot과 월운 평가 순서를
재현해 확인해야 한다. weakened여도 도달 입증 시 같은 weaken이다.
A I-02의 용신 투출 규칙과 I-03의 원고 용어 보정은 구별해 확인한다.
C의 원고 표기나 원국 상신 기술을 현재 scope의 독립 역할 결과로
복사하지 않는다.

5. 추가 규칙 또는 증빙이 필요한 Effect Fact
- 丙 편인 — C-09 계열 십성 산출과 현재 기능 귀속을 연결하고, 월운
  壬 → 丙의 실제 적용 근거를 등록한다. 관계 fact만으로는 부족하다.
- 丙 용신·상신 — 각각 별도의 현재 역할 판정과 기능 귀속·도달이
  필요하다. 용신은 I-02 적용 결과, 상신은 I-03에 따른 구조 보조
  기능의 판정 근거를 확인한다. 문서의 양쪽 명칭만으로 이중 확정하지
  않는다. 현행 규칙으로 별도 귀속·작동을 판정할 수 없다면 해당
  기능의 판정 규칙을 보완하고 그 행은 보류한다.
- 壬 편재 — 일간 戊가 월운 壬에 능동적으로 작용하는 경로가 운영상
  유효하며 편재 기능까지 도달하는지 확인한다. OP-T04는 일간합
  규정이다. 해당 방향의 적용 근거가 없으면 일간의 극 참여 및
  도달 규칙을 보완할 때까지 보류한다.
- 공통 — 단순 생극 조합과 실제 도달을 구분하는 적용 근거가 필요하다.
  통관·보호·정지 등의 우선순위가 미확정이면 해당 효과를 보류한다.
  추가 약화의 합산, 타 scope 자동 승계 및 병 확정·구응 전환은 각각
  독자적인 규칙이 필요한 후속 판단이다.

6. 범용 EffectFact contract 설계 가능 여부 — YES
필수 필드
  contractVersion, effectId, sourceEntityId, targetEntityId,
  targetFunctionId, relationFactId, effectType, scopeId,
  runtimeStateRefs, roleStateRefs, ruleIds, evidenceIds,
  provenance, effectivePeriod, status

천간 극 규칙에서 effectType은 weaken으로 고정한다. 범용 contract의
stop은 별도 정지 규칙과 적용 근거를 요구한다. 기존 GuEungEffectFact는
병 손상 경로의 구응 효과를 나타내므로 현재 contract를 그대로 유지한다.

targetFunctionId는 entity 귀속, 기능 종류 및 식별자, 현재 scope의
작동 여부와 근거를 가진 기능 사실을 참조한다. 십성 기능은 검증된
십성 산출을 참조하며 roleStateRefs는 빈 배열이 가능하다. 구조 역할
기능은 현재 scope에서 독립 평가되고 불확실성이 해소된 해당 역할
참조가 필요하다. 문서 진술·expected는 runtime 입력으로 쓰지 않는다.

confirmed 검증은 등록된 관계의 방향, 존재·판정 상태, source·target
RuntimeState, 기능 귀속·작동, 규칙 적용·도달 증거를 교차 확인한다.
runtimeStateRefs는 양쪽 상태를 포함한다. effectivePeriod는 scope와
모든 필수 근거의 유효 범위가 겹치는 구간이며 평가 시각을 포함한다.
provenance에 producer·버전·입력 fact 및 규칙 적용 참조를 남긴다.
동일 scope·관계·기능·효과 유형·적용 기간의 재처리는 같은 ID를
사용한다. 불충분한 근거는 진단으로 남기고 confirmed 발행을 보류한다.
동일 관계의 여러 기능이 해석에서 하나의 구조 손상을 가리킬 경우
병·구응 또는 길흉의 근거를 중복 집계하지 않는다.

7. producer 구현 시작 가능 여부 — NO
운영 producer에 앞서 A 규칙 문안 및 적용 ID, 도달 판정 근거,
현재 범위의 기능·역할 참조, 2027.02 합·승계 처리와 일간 戊 경로의
독립 검증이 필요하다. 합성 테스트의 네 조건부 결과는 설계 검토로
승인 가능하다. 이번 작업은 TXT 보고서만 작성했으며 코드와 기존
문서는 수정하지 않았다. 실행 테스트는 수행하지 않았다.
