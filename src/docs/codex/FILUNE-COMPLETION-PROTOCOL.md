# FILUNE Completion Protocol

## 1. 최상위 목표

기존 전문가 원문과 확정된 Master를 바탕으로 정확하고 일관된 FILUNE 사주풀이 엔진 및 고객용 풀이를 완성한다.

새로운 설계와 문서 작성 자체를 성과로 간주하지 않는다.

## 2. 고정 작업 순서

### Phase 1. 종합 구조 판정 완성

- 월령·격국·용신
- 정격·변격·겸격
- 비견·겁재·양인
- 천간 생·극·합·합거
- 지지 형·충·회·합·파·해
- 반합·삼합·방합
- 통근·십이운성·작용력
- 생조·설기·강화·약화
- 상신·병·구응
- 경쟁 경로 및 보호 경로
- 대운·세운·월운·일운의 상호작용
- 천간·지지·전체 성패
- 궁성 효과

개별 관계의 존재 여부가 아니라 모든 관계와 작용력이 반영된 최종 구조 판정을 완성한다.

### Phase 2. 분야별 통변 완성

확정된 구조 판정을 기존 Outcome 및 Cause-to-Life Mapping을 통해 현실 영역에 연결한다.

- 재물
- 직업·사업
- 학업·문서
- 인간관계
- 연애·결혼
- 건강 관련 전통적 해석
- 성향 및 행동
- 현재와 미래의 운

분야별 판단은 서로 독립적으로 보존한다.

### Phase 3. 전문가 사례 검증

기존 전문가 사례를 현재 엔진에 적용한다.

- 전문가 판단과 FILUNE 판단 비교
- 구조적 원인 비교
- 최초 불일치 지점 확인
- 공통 실행 오류 수정
- 반례 및 기존 정상 사례 회귀 검증

사례별 하드코딩을 금지한다.

### Phase 4. 고객용 풀이 완성

확정된 Judgment와 Outcome을 사용한다.

고객용 풀이는 다음 순서를 따른다.

결론 → 구체적 원인 → 현실에서의 작용 → 도움 및 악화 조건 → 시기 → 판단 및 활용 방법

KO·JA·EN은 동일한 의미 구조에서 각 언어로 직접 생성한다.

### Phase 5. 서비스 통합 검증

실제 BirthInput부터 최종 고객 결과까지 검증한다.

- 만세력 계산
- 구조 판정
- 분야별 통변
- 상품별 Assembly
- KO·JA·EN Renderer
- 고객 화면
- 회귀 검증
- Build
- Git commit 및 push

## 3. 중복 작업 방지 원칙

새 작업을 시작하기 전에 반드시 다음을 확인한다.

1. 기존 Master에 이미 정의되어 있는가?
2. 기존 코드에 이미 구현되어 있는가?
3. 기존 검증 및 감사 결과가 존재하는가?
4. 실제 고객 풀이에서 확인된 문제가 무엇인가?
5. 공통 원인을 수정하면 해결되는가?

이미 완료한 연구, 감사, 설계 및 검증은 새로운 문제가 확인되지 않는 한 반복하지 않는다.

## 4. 오류 해결 원칙

실제 결과의 불일치를 발견하면 최초 불일치 지점을 찾는다.

기존 설계가 올바르면 구현을 수정한다.

기존 구현이 올바르지만 규칙의 근거가 부족하면 기존 전문가 원문을 확인한다.

기존 설계와 구현 모두에 문제가 없다면 후속 Outcome 또는 Renderer 연결을 확인한다.

개별 오류 때문에 전체 작업 순서를 변경하지 않는다.

## 5. 금지사항

- 동일한 결론의 반복 문서화
- 목적 없는 전체 재감사
- 기존 기능을 확인하지 않은 신규 설계
- 불필요한 schema, projection, registry 추가
- 사례별 예외 하드코딩
- 근거 없는 policy 확대
- 임의 점수 및 가중치 도입
- 상위 판정 오류를 Renderer에서 보정
- 미확정 판정을 고객에게 확정적으로 표현
- 실제 날짜가 없는 전문가 사례의 날짜 추정

## 6. 단계 완료 기준

문서 작성이나 개별 테스트 PASS만으로 단계를 완료했다고 판단하지 않는다.

해당 단계의 실제 입력부터 최종 산출물까지 연결되고, 기존 승인 규칙과 일치하며, 관련 회귀 검증을 통과해야 한다.

검증 과정에서 발견된 구현 오류는 기존 근거가 충분하면 해당 작업에서 직접 수정한다.

사용자에게 이미 완료된 작업을 다시 수행하도록 요구하지 않는다.

## 7. AI 및 Codex 작업 책임

AI는 다음 작업을 선제적으로 판단하고 제안한다.

- 현재 작업이 기존 작업과 중복되는지
- 현재 단계에서 반드시 해결해야 할 문제가 무엇인지
- 어떤 작업을 생략할 수 있는지
- 다음 단계로 진행할 수 있는지
- 기존 전문가 규칙에 실제로 부족한 부분이 있는지

사용자의 질문에 따라 전체 진행 방향을 임의로 변경하지 않는다.

진행 방향을 변경해야 한다면 기존 계획을 유지할 수 없는 구체적인 근거를 제시한다.

## 8. 권위 및 우선순위

명리 판단 및 구현의 권위는 기존 승인된 Authority와 Master에 있다.

이 문서는 작업 순서와 완료 기준을 정의하며, 새로운 명리 판단 규칙을 생성하거나 기존 Master를 변경하지 않는다.
